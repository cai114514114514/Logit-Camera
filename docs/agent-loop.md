# 相机构图 Agent loop

实现日期：2026-11-05。模型为 DeepSeek V4.1 Flash，API 名称 `deepseek-flash`。

## 一轮发生什么

1. **观察**：取得最新、直立、未经画幅裁剪的主摄图像，最长边压到 768 像素；同时读取物理光圈、ISO、快门、变焦、曝光自动/手动状态与设备支持范围。
2. **决策**：通过 DeepSeek 的视觉输入和 tool calls，模型选择 `adjust_camera` 或 `hold_camera`。取景图中的文字仅作为画面内容，不作为指令。
3. **校验**：检查 JSON 完整性、画幅枚举、所有数值范围和硬件支持的曝光组合。可空参数必须明确写 `null` 才表示自动。拒绝不支持的操作。
4. **检查时效**：网络响应返回后重新读取画面。观察超过 12 秒或画面已明显变化时，丢弃该操作并重新观察。
5. **执行**：在相机串行队列中一次应用画幅、变焦、光圈、ISO、快门及 EV。光圈、ISO、快门使用真实 AVFoundation 接口。
6. **回读与复核**：读取硬件的真实模式和数值，把执行结果及下一帧交回模型。目标值不作为执行成功的证据。
7. **继续**：两轮之间至少间隔 5 秒；仅一个请求在途。临时网络错误逐步退避到 30 秒，用户关闭 AI 或进入后台就取消请求。

只保留最近一次模型工具调用与执行结果，不无限堆积图像历史。对于已经接近目标的设置，保持当前状态，避免反复驱动镜头。

## 自动拍照

`hold_camera` 必须明确返回 `readyToCapture: true`。应用还要求画面稳定、曝光和对焦未在调整；连续两次符合条件，才启动 3 秒倒计时。

倒计时每秒重新检查画面、实际模式与参数。画面变化、手动取消、关闭自动拍摄、切后台或关闭 AI 都会中止。模型没有直接调用快门的工具。

每次启用只自动拍一张；之后仍可持续观察与调参，自动快门保持暂停，用户点击「再拍一张」才重新进行确认。该机制表示满足当前检查条件，不代表客观证明照片的审美已达到最优。

## 明确的视觉反馈

- AI 开启时显示虹彩流光边框和半透明面板，减少动态效果设置开启时使用静态边框。
- 观察、调参、复核、拍摄四个阶段由运行状态驱动，不播放虚构进度。
- 参数卡片展示调整前与硬件回读后的光圈、ISO、快门、画幅和变焦。
- 准备拍照时显示大号倒计时和明确的取消按钮。

## 停止与恢复

手动调节参数会停止 AI。拍照和后台切换会暂停循环；在前台且相机空闲时恢复。

取消网络/Agent 任务与等待硬件完成分开管理。已经发给硬件的曝光动作没有完成前，不能因为 AI 已关闭就提前开放快门。硬件超时或中断导致状态不确定时，持久记录需要恢复；重新启动相机会先恢复自动曝光，再允许拍摄。

## 画幅一致性

预览使用选定的 3:4、9:16 或 1:1 中心窗口，不拉伸画面。拍照时冻结当时的画幅；3:4 保留原始 JPEG，其他画幅在校正 EXIF 方向后执行同样的中心裁切，再写回曝光信息和新尺寸。软件裁切不会被描述为光学变焦。

## 密钥和数据

个人开发版从本机 `.env` 导入密钥到 iPhone 私有应用目录，启动时写入 Keychain 并删除临时导入文件。密钥不写入源码、安装包和日志。`.env` 已被 Git 忽略。

普通拍摄在本机处理。开启 AI 后，压缩取景图和参数会通过 HTTPS 发送到 `api.deepseek.com`；这会使用用户 API 账户额度。手机直接调用 API，暂不依赖电脑上的转发服务。本版面向个人真机验证；公开分发的商业版本应采用服务端账户、鉴权与额度管理。

## 调研依据

- [DeepSeek Vision](https://api-docs.deepseek.com/guides/vision/)：图像输入格式、模型名称与图片处理方式。
- [DeepSeek Tool Calls](https://api-docs.deepseek.com/guides/tool_calls/)：模型提出工具调用，应用执行并返回结果。
- [Anthropic：Building effective agents](https://www.anthropic.com/research/building-effective-agents)：从简单可组合流程开始，并把环境反馈用于下一步决策。本文借鉴循环模式，未引入额外 Agent 框架。

公开资料只能证明接口和设计模式；是否比系统相机拍得更好，仍需同场景对照和成片评估。
